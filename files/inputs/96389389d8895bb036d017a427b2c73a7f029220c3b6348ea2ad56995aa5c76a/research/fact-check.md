## 三、六个主题

### 1. 能力
- 【厂商】见 F1、F3。
- 【独立】S3 指出公开部署模型通常能触发崩溃，但任意代码执行并不常见。
- 【不确定】尚无本项目可采用的独立第三方复现；CAISI 评估因访问失败不采用。

### 2. 可获得性
- 【事实】S4：权重在 Hugging Face 公开可获取，另有第三方推理服务。S5：Z.ai 官方提供 API。
- 【不确定】许可条款与发布日期均未核实，标“未知”。
- 【推论】权重公开后，副本可被下载、本地运行与修改，厂商无法回收。

### 3. 补丁窗口
- 【独立】S6：2023 年 TTE 统计（138 个样本，剔除 15 个异常值后 123 个平均 5 天，未剔除 47 天），且为保守估计。这是相对补丁发布的时间，不是所有漏洞披露后的平均。
- 【推论】若 F3 一类能力普及，可能进一步压缩修补时间；但 S6 数据早于 GLM-5.3，无法直接证明这一点。

### 4. 开放权重的利弊
- 【推论】收益：便于审计、研究、自托管和数据不出本地。此为一般推论，S4 模型卡未就此作出可核实陈述。
- 【厂商】风险：见 F2。
- 【独立】S10 记录有威胁行为者在被入侵环境部署本地开放权重模型，以规避商业 API 监控（不涉及 GLM-5.3）。
- 关键限定：厂商的 API 监控和账户封禁无法直接控制独立的本地副本；但模型内置的拒绝行为不会因本地部署自动消失，仍可能存在，只是可被下游修改。S9 显示其 2024 年实验的模型拒绝行为可被定向削弱，但不能据 F2 推定同一机制适用于 GLM-5.3。

### 5. 评测局限
- 厂商自测结果的限定见 F1、F2、F3。
- S3、S9 仅读摘要。
- S10 存在可见性偏差，且不涉及 GLM-5.3。

### 6. 防守启示
- 【厂商】S1 呼吁防守方更多使用前沿模型、政府独立测试、开放权重开发者加强防护。
- 【独立】S6 建议加快修补、按利用难度与价值排序、网络分段与访问控制、假设利用必然发生。
- 【独立】S10：Google 对涉及滥用的资产采取禁用等处置。【推论】这类处置只对服务商自有服务有效。
- 【推论】对本地副本，防守重心应转向缩短修补周期与纵深防御，而非依赖模型提供方的管控。
